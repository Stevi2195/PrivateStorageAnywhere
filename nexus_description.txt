[size=4][b]Private Storage Anywhere PLUS[/b][/size]

[line]

Open your [b]Private Storage[/b] and all five [b]Housing Storage Chests[/b] (Gatherables, Dresser, Refrigerator, Symbol, Collecting) from anywhere in the world with a single hotkey or controller button press. No need to walk back to your camp or housing chests.

[line]

[b]Final version.[/b] v1.6.0 for game version [b]2.02.00[/b] is the last update; the mod is no longer maintained. The complete source code is public on [url=https://github.com/Stevi2195/PrivateStorageAnywhere]https://github.com/Stevi2195/PrivateStorageAnywhere[/url] — MIT-licensed, so anyone is welcome to pick it up and continue it.

[line]

[size=3][b]Features[/b][/size]

[list]
[*][b]F4[/b] to open Private Storage (Camp Warehouse) from anywhere
[*][b]F5[/b] to open the [b]Gatherables Chest[/b] from anywhere
[*][b]F6[/b] to open the [b]Dresser[/b]
[*][b]F7[/b] to open the [b]Refrigerator[/b]
[*][b]F8[/b] to open the [b]Symbol Storage[/b]
[*][b]F9[/b] to open the [b]Collecting Storage[/b]
[*]Pre-bound controller combos: [b]LB + LeftStick[/b] (Xbox) / [b]L1 + L3[/b] (PS) for Private Storage; [b]LB + RightStick[/b] (Xbox) / [b]L1 + R3[/b] (PS) for Gatherables. The other chests are unbound by default — assign them in the INI if desired.
[*]Press the same key/button again to close. To switch chests, close one and press the next chest's binding.
[*]Each chest also supports optional XInput controller buttons + modifier and PS5/PS4 (DualSense/DualShock 4) buttons, all configurable in the INI.
[*][b]ESC[/b] to close
[*][b]Native UI:[/b] Uses the game's built-in warehouse interface — no custom overlay
[*][b]Localized titles:[/b] Every panel title (Private Storage, Gatherables, Dresser, Refrigerator, Symbol, Collecting) automatically matches your game language — all 14 supported languages (KR/EN/JP/RU/TR/ES/MX/FR/DE/IT/PL/BR/TW/CN)
[*][b]Full interaction:[/b] Move items in and out of every chest, same as at the chest in person
[*][b]Private Storage works immediately[/b] after game start, no NPC visit required. [b]Housing chests[/b] (Gatherables, Dresser, Refrigerator, Symbol, Collecting) need an NPC visit once per game session before the mod can display their contents.
[*][b]Update-proof:[/b] Uses automatic pattern scanning, vtable matching, and runtime string cross-references to locate internal game functions instead of hardcoded offsets
[*][b]Compatible with UI mods:[/b] Identifies the warehouse panel by vtable signature, not by panel ID — works correctly even when mods like "No Letterbox" change the UI configuration
[*][b]Modal-aware close:[/b] ESC, B and Circle first dismiss an open quantity or details popup before closing the storage
[*][b]Configurable:[/b] Each chest hotkey can be reassigned via INI file
[*][b]Keyboard modifiers:[/b] Optional modifier key support (e.g. Shift+I to open storage while plain I opens inventory)
[*][b]Xbox / XInput controller:[/b] Assign a controller button to any panel. Supports an optional modifier button (e.g. hold LB + LeftStick for Private). Works with Xbox controllers natively and all other controllers through Steam Input.
[*][b]PS5 / PS4 controller:[/b] Native HID support for DualSense and DualShock 4 — close warehouse with Circle or any configured button. Default for Private is L1 + L3, for Gatherables L1 + R3. Configurable PSButton/PSModifier per panel (Share, Options, Circle, Triangle, Square, Cross, L1, R1, L3, R3, Touchpad, PS, Mute).
[*][b]INI hot-reload:[/b] Press F11 to reload all settings without restarting the game
[/list]

[size=3][b]Configuration[/b][/size]

Edit [b]PrivateStorageAnywhere.ini[/b]:

[code][Settings]
Enabled=1                          ; Master switch (0=off, 1=on)
DebugLog=0                         ; Create log file for troubleshooting
ReloadKey=7A                       ; Reload INI without restart (7A = F11)

; --- Panel 0 — Private Storage (default: F4 / LB+LeftStick / L1+L3) ---
PrivateHotkey=73
PrivateControllerButton=0040       ; LeftStick
PrivateControllerModifier=0100     ; LB
PrivatePSButton=L3
PrivatePSModifier=L1

; --- Panel 1 — Gatherables Chest (default: F5 / LB+RightStick / L1+R3) ---
GatherablesHotkey=74
GatherablesControllerButton=0080   ; RightStick
GatherablesControllerModifier=0100 ; LB
GatherablesPSButton=R3
GatherablesPSModifier=L1

; --- Panel 2 — Dresser (default: F6) ---
DresserHotkey=75

; --- Panel 3 — Refrigerator (default: F7) ---
RefrigeratorHotkey=76

; --- Panel 4 — Symbol Storage (default: F8) ---
SymbolHotkey=77

; --- Panel 5 — Collecting Storage (default: F9) ---
CollectingHotkey=78[/code]

Each binding is a panel toggle: opens that panel from cold, or closes the warehouse if any panel is open. Set any [b]<Name>Hotkey[/b] / [b]<Name>ControllerButton[/b] / [b]<Name>PSButton[/b] to 00 (or empty) to disable.

A full Windows Virtual Key Code reference is at the bottom of the INI file.

[size=3][b]Controller Setup[/b][/size]

Each panel has its own [b]<Name>ControllerButton[/b] and optional [b]<Name>ControllerModifier[/b]. Example to bind Refrigerator to [b]LB + D-Pad Up[/b]:

[code]RefrigeratorControllerButton=0001    ; D-Pad Up
RefrigeratorControllerModifier=0100  ; LB[/code]

[b]Controller button values:[/b] DPAD_UP=0001, DPAD_DOWN=0002, DPAD_LEFT=0004, DPAD_RIGHT=0008, START/MENU=0010, BACK/VIEW=0020, LEFT_STICK=0040, RIGHT_STICK=0080, LB=0100, RB=0200, A=1000, B=2000, X=4000, Y=8000

[b]Non-Xbox controllers via Steam Input:[/b] Switch and other non-Sony controllers are supported through Steam Input, which translates them to XInput automatically.

[size=3][b]PS5 / PS4 Controller Setup[/b][/size]

Each panel has its own [b]<Name>PSButton[/b] and optional [b]<Name>PSModifier[/b] for DualSense / DualShock 4. Example to bind Refrigerator to [b]L1 + Triangle[/b]:

[code]RefrigeratorPSButton=Triangle
RefrigeratorPSModifier=L1[/code]

[b]Supported PSButton values:[/b] Share, Options, Circle, Triangle, Square, Cross, L1, R1, L3, R3, Touchpad, PS, Mute

The close action is deferred to button release to prevent triggering a dodge roll in gameplay. Supports DualSense, DualSense Edge, and DualShock 4 v1/v2 over USB and Bluetooth.

[size=3][b]Antivirus Notice[/b][/size]

Some antivirus programs may flag this mod because it relies on low-level hooking to access the game's internal panel functions directly.

Crimson Desert does not provide an official mod API for this functionality, so the mod has to locate and call internal game functions in memory. That kind of behavior can look suspicious to antivirus software even when the mod itself is not malicious.

[b]v1.5.10[/b]
[list]
[*][b]Fixed:[/b] A housing chest could briefly show its vanilla capacity ([b]10[/b] slots instead of [b]1000[/b]) when opened right after a teleport or loading a save. The game resets the slot count on those transitions and the mod only re-applied it on a background timer, so there was a short window where a chest opened at the old capacity. The expansion is now re-applied the instant you open a storage, so it is always at full capacity.
[*][b]Update-safety:[/b] the mod now auto-detects the internal "warehouse mode" index that Pearl Abyss reshuffles on almost every patch. That value was previously hardcoded and had to be re-found by hand after each update — a wrong value silently killed all storage hotkeys. It is now derived from the game's own code at startup and cross-checked, so this class of breakage should no longer happen on a routine patch.
[*][b]Hardening:[/b] two internal writes that relied on fixed struct offsets are now self-validating — if a future update moves the field, the mod skips the write and degrades gracefully instead of risking a delayed crash.
[*]No changes to features, keybindings, or on-screen behaviour.
[/list]

[b]v1.5.9[/b]
[list]
[*]Fixed: The [b]top header title[/b] shows the specific chest name again (Private Storage, Gatherables, Dresser, Refrigerator, Symbol, Collecting) — the known limitation of v1.5.8 is resolved. The 1.13 update had not removed the internal title hook after all: it recompiled the title function (so the mod no longer recognized it) and moved the title element inside the warehouse controller. The mod now derives both from the game's own UI binding data at startup, with a built-in cross-check that cleanly disables the title override if a future update changes the layout again — worst case is a generic title, never a crash.
[/list]

[b]v1.5.6[/b]
[list]
[*]Updated for game version [b]1.10.01[/b].
[*]Fixed: After opening any storage via the mod, [b]store-type menus stopped appearing[/b] — vendor buy/sell, camp provisions, bank, mission dispatch and cooking-result screens opened the NPC interaction (camera zoomed in) but showed no UI, forcing Alt+F4. Two related leftovers from the 1.5.5 view-mount caused this: the game's internal menu-layer state stayed flagged "open" after closing a storage (the game's own menu opens only fire when that flag [i]changes[/i], so later requests were silently swallowed), and the menu-layer request byte was never returned to its idle value, which kept the player permanently flagged as "in a cinematic" — the cinematic mode shadowed the store mode, which is why the camera zoom still played but no menu ever mounted. The mod now parks the menu-layer in exactly the state the game itself uses when idle, on every close path.
[*]Fixed: Pressing a storage hotkey while a game menu was still closing (e.g. immediately after leaving a shop, or after skipping the cooking animation) created an invisible "ghost" session that blocked all other UI until restart. The open is now aborted cleanly in that situation — press the hotkey again a moment later and it works normally.
[*]Fixed: The HUD interaction prompt could stay hidden after using mod storages (same root cause as above).
[*]New: The [b]item category tabs[/b] (bag / armor / weapon / food / scroll / gem icons above the grid) now appear on hotkey-opened storages — they previously only showed when opening a storage at its NPC. The mod now asks the game to build the category bar through its own inventory path, so it works the same as a normal warehouse open. Item display is unchanged.
[*]Internal: removed a broken event-queue call that silently failed on every storage open since 1.5.5.

[b]v1.5.5[/b]
[list]
[*]Updated for game version [b]1.10.00[/b].
[*]Fixed: F-key hotkeys hid the HUD but no warehouse panel appeared after the 1.10 update. Pearl Abyss shifted the sub-mode enum: the mod's "open warehouse" mode-flag pattern derived [i]sub-mode 5[/i] (alert/cinema) instead of [i]sub-mode 6[/i] (dialog/store). The warehouse HTML view is only mounted by the panel-manager when the current mode-tag list contains "store", so the panel stayed unmounted and invisible. The mod now sets the subtype flag at index 6, which makes the game's tick-based mode resolver derive sub-mode 6 on the next frame, the panel-manager mounts the warehouse view, and the panel renders normally.

[b]v1.5.3[/b]

[*]Fixed: Hotkey could open the warehouse during the [b]loading screen[/b] (and other non-gameplay states). [b]v1.5.2[/b]
[list]
[*]Updated for game version [b]1.08.00[/b].
[*]Fixed: Top title at the warehouse window was stuck on the game's default "Camp Provision" / "UI_WareHouse_Title" text for every panel — in 1.08 the warehouse handler stopped writing the top title via SetTitle, so the mod's static resolver couldn't find the node. [*]Improved: Drift-resistance for future game updates.

[*]HGM string slot resolved dynamically via the "Housing_GatheredMaterials" string-xref (LEA+MOV-RIP pattern) instead of a 1.06 hardcoded RVA.
[*]Container vtable starts unset and is filled via auto-relearn, now requiring 5 consecutive sightings of the same vtable pointer before adopting it. Prevents the previous single-frame stale adoption that could crash on later SetInventory.
[*]Cleared all remaining 1.06 hardcoded RVAs (WarehouseRefresh / ContainerWalker / SubObjectResolver / ContainerMarker) — these were inside disabled call paths since 1.06 and would silently drift on future patches.
[*]One-shot prolog sanity check at the first FilterRender call — if the bytes don't look like a function prolog, the log emits a clear WARN instead of jumping into wrong code.

[*]Cleanup: ~560 lines (~10% of the source) of dead diagnostic code removed. The most impactful removal was an unused hardware-breakpoint subsystem (Vectored-Exception-Handler + per-thread DR0/DR7 register manipulation via Toolhelp thread enumeration). It was never actually armed at runtime, but the API combination matches anti-debug / process-injection patterns that antivirus heuristics and Chrome SafeBrowsing flag as suspicious. Also removed: five unused filter-hook diagnostic capture functions, the SetTitle diagnostic hook used to find the top-title node, a per-Handler-call packet-byte dump, a dead BindRefresh fallback chain, and RTTI heap-scan helpers.
