Private Storage Anywhere — Changelog

v1.4.1 (2026-04-27)
- New: Per-chest XInput controller buttons (with optional modifier) — every chest can be bound to any controller button combination via the INI.
- New: Per-chest PS5/PS4 (HID) buttons — every chest can be bound to any DualSense/DualShock 4 button (Share, Options, Circle, Triangle, Square, Cross, L1, R1, L3, R3, Touchpad, PS, Mute) via the INI.
- Changed: Symbol Storage hotkey is disabled by default (was F12). Its in-game purpose is currently unclear; users who know what it is can re-enable it manually via the INI.

v1.4.0 (2026-04-26)
- New: All 5 housing chests can now be opened from anywhere with their own hotkeys — F7 Gatherables, F8 Dresser, F9 Refrigerator, F12 Symbol, Num0 Collecting. Each hotkey toggles its panel open/close. To switch chests, close one and press the next chest's hotkey.
- New: Per-chest hotkey configuration in the INI — every chest has its own hotkey/modifier you can reassign without recompiling.

v1.3.3 (2026-04-23)
- Updated for game version 1.0.4.1 — Apr-23 update reorganized the internal warehouse struct layout and changed several function prologs. All affected offsets, scanners, and hook installer re-adapted.
- Fixed: Hook installed at the wrong address after the update — the warehouse Handler's prolog changed from `MOV [RSP+8], RBX` to `MOV [RSP+0x10], RBX`; FindFunctionStart didn't recognize the new form and fell through to a nearby JMP thunk. Prolog matcher generalized to accept any stack slot.
- Fixed: Warehouse struct fields shifted by +0x20 in the 0x2C8–0x330 range. Donation state (3 faction shorts) moved from 0x330 to 0x350, the 0x15 prepare sub-object offsets moved from 0x2C8/0x2D8/0x300 to 0x2E8/0x2F8/0x320. Both resolved dynamically at startup.
- Fixed: "Donate Funds" keyguide stayed visible on Private Storage — the Apr-23 HTML template made this widget default-visible (previously default-hidden). Mod now explicitly hides the donation sub-controller via the game's own hide function immediately after the 0x15 prepare.
- Fixed: ESC no longer closes the warehouse while a quantity/confirm modal is open — the modal-dialog pointer moved from handler+0x360 to handler+0x258 (completely different struct slot, not a +0x20 shift like the other fields).
- Fixed: Panel-close no longer generates a log exception — the base-class "hide panel" command null-derefs for mod-opened panels. Mod now does the three state clears directly (active flag, panel value, scene render-bit) with null-safe dereferencing of the scene-object chain.
- Fixed: Warehouse no longer opens from the Ingame-Menu state. Apr-23 shifted the sub-mode enum values: the old 0x0E (pre-update "normal gameplay") now means "ingamemenu". Open-whitelist is now explicit: 0x0D, 0x0F, 0x10.
- Fixed: SetDonationFaction function resolution — its prolog changed in Apr-23 (the old exact-prolog filter rejected it). Resolver now filters by call-target proximity to the Handler (library calls like strcmp sit far away, the real command handler is co-located within ~1 MB), so future prolog changes won't break donation-state cleanup.
- Added: INI setting `PanelId=<hex>` — default 0 (auto-capture first seen, legacy behavior). Apr-23 introduced multiple warehouse types (Camp, Private, Kuku Food Storage, Collectibles, Wardrobe); set a specific panelId hex to pin the mod to one variant.
- Added: Diagnostic log line listing every warehouse-vtable instance seen by CanShow with its panelId, so users can discover which ids the game registers for the new types.

v1.3.2 (2026-04-12)
- Updated for game version 1.0.3.1 — internal game functions were restructured and had to be re-adapted.
- Improved: Hook installer and pattern scanners updated to handle new code layout introduced by this game update.

v1.3.1 (2026-04-11)
- Fixed: Wrong keyguide shown after visiting a donation NPC (e.g. "Donate Funds" instead of "Store") — the mod's direct SetInventory call bypassed the game's 0x15 command dispatch, which runs three "prepare" methods on sub-objects at +0x2c8/+0x2d8/+0x300 that reset stale UI state including keyguide bindings. Now sends an empty 0x15 command to trigger these prepare calls before loading inventory.
- Fixed: On the very first F6 after loading a save the 0x0e "show panel" command was skipped because the warehouse controller had not been captured yet (auto-capture only fires once the game calls CanShow on the panel, which happens during ModeSwitcher). The command is now retried after ModeSwitcher once the handler becomes available.
- Fixed: Dynamic bottom-label offset resolver — handles the +8 shift from +0x300 to +0x308 introduced by the 2026-04-11 update, and is now derived at runtime from the handler's SetWareHouseInventoryName branch (previously the 2026-04-11 update caused random crashes because the mod was writing text to a sub-object pointer at +0x300).
- Fixed: Dynamic ModeSwitcher offset resolver — scans for disp32 values in the mainChar mode-byte range using both plain [reg+disp32] and SIB-encoded [reg+index+disp32] operand forms (the array loops use SIB).
- Fixed: Dynamic CanShow active-flag resolver — strict pattern (MOVZX EAX from byte field followed by RET within 6 bytes) rules out unrelated virtual functions that previously matched loose MOVZX heuristics.
- Improved: All struct offsets (active flag, mainChar mode bytes, bottom label, donation state) are now resolved dynamically from game code at startup, so future updates that shift these offsets no longer require a rebuild.

v1.3.0 (2026-04-11)
- Fixed: Random crashes after 2026-04-11 game update — the warehouse handler struct was reorganized, shifting the bottom-label pointer from +0x300 to +0x308; the mod was writing UI text to the wrong address (a sub-object pointer), corrupting memory
- Improved: All struct offsets are now resolved dynamically at startup instead of being hardcoded constants — the mod scans CanShow, ModeSwitcher and the warehouse handler to extract active flag, mainChar mode bytes, and bottom-label offsets directly from the game code. Future updates that shift these offsets should no longer require a mod rebuild.

v1.2.6 (2026-04-05)
- Fixed: F6 and controller toggle button could close the warehouse while a modal dialog (quantity/confirm) was still open — now blocks close when any modal is active
- Fixed: Phantom modal bug — stale dialog pointer from previous camp NPC warehouse visits could make the mod think a modal was active when nothing was visible, preventing ESC from closing the warehouse. Modal pointer is now cleared on every F6 open.

v1.2.5 (2026-04-04)
- Fixed: Auto-capture no longer locks permanently onto the wrong panel — the previous vtable range check was tautological (always matched any nearby panel) and the reset after failed validation was a no-op, causing the warehouse controller to never be found after a wrong panel was checked first
- Improved: Auto-capture now uses exact vtable match instead of offset-based range check — vtable start is resolved at init via RTTI Complete Object Locator scan, uniquely identifying the UIGamePlayControlRootWarehouse2 class

v1.2.4 (2026-04-04)
- Fixed: Auto-capture no longer grabs the wrong UI controller when other panels share the same vtable (base class) — now validates warehouse-specific UI nodes (+0x0E0 top title, +0x300 bottom label) before accepting a controller
- Fixed: Modal dialog offset scan now collects all matches and picks the largest (warehouse-specific) offset instead of stopping at the first match (base class offset)

v1.2.3 (2026-04-04)
- QOL: Cursor is hidden immediately when closing the warehouse
- Improved: CanShow detection is now update-proof — primary vtable scan identifies CanShow by its +0x118 signature instead of relying on a fixed vtable offset, fallback pattern scan kept as safety net

v1.2.2 (2026-04-04)

- Fixed: Panel show/hide now uses the game's own base-class handler commands (0x0e/0x0f) instead of manually setting internal flags — this is more robust and survives future game updates
- Removed: Unsafe 0x15 cache-clear call that crashed after the update (sub-objects at handler+0x2c8/0x2d0/0x2f8 are only initialized after NPC interaction)
- Removed: Cursor force-show/hide — game now handles cursor visibility in storage menus natively
- Improved: Language detection is now update-proof — the language byte address is resolved dynamically at runtime by scanning the Steam API language init function
- Improved: Modal dialog detection (quantity/confirm dialogs) is now update-proof — the handler struct offset is resolved dynamically at runtime via string-xref + code pattern scan instead of being hardcoded
