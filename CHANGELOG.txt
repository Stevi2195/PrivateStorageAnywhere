Private Storage Anywhere — Changelog

v1.2.4 (2026-04-04)
- Fixed: Auto-capture no longer grabs the wrong UI controller when other panels share the same vtable (base class) — now validates warehouse-specific UI nodes (+0x0E0 top title, +0x300 bottom label) before accepting a controller
- Fixed: Modal dialog offset scan now collects all matches and picks the largest (warehouse-specific) offset instead of stopping at the first match (base class offset)

v1.2.3 (2026-04-04)
- QOL: Cursor is hidden immediately when closing the warehouse
- Improved: CanShow detection is now update-proof — primary vtable scan identifies CanShow by its +0x118 signature instead of relying on a fixed vtable offset, fallback pattern scan kept as safety net

v1.2.2 (2026-04-04)
- Fixed: Compatible with game update 2026-04-04 — warehouse panel now renders correctly after the update changed the scene registration system
- Fixed: Panel show/hide now uses the game's own base-class handler commands (0x0e/0x0f) instead of manually setting internal flags — this is more robust and survives future game updates
- Removed: Unsafe 0x15 cache-clear call that crashed after the update (sub-objects at handler+0x2c8/0x2d0/0x2f8 are only initialized after NPC interaction)
- Removed: Cursor force-show/hide — game now handles cursor visibility in storage menus natively
- Improved: Language detection is now update-proof — the language byte address is resolved dynamically at runtime by scanning the Steam API language init function
- Improved: Modal dialog detection (quantity/confirm dialogs) is now update-proof — the handler struct offset is resolved dynamically at runtime via string-xref + code pattern scan instead of being hardcoded

v1.2.1 (2026-04-03)
- Fixed: ESC now correctly closes the quantity dialog ("How many do you want to move?") before closing the warehouse — previously ESC closed the warehouse while the dialog stayed visible
- Fixed: Window detection now uses the exact game window class name instead of blind enumeration, preventing WndProc hook failures (error=1400) caused by overlays
- Added: Game window class/title logged on startup for easier troubleshooting

v1.2.0 (2026-04-01)
- New: Localization — warehouse title now automatically matches the game language (14 languages: KR, EN, JP, RU, TR, ES, MX, FR, DE, IT, PL, BR, TW, CN)
- New: Top title (handler+0x0E0) now set correctly via SetTitle — found live text setter node through CSS tree scan
- New: Bottom label (handler+0x300) uses localized title instead of hardcoded English
- New: Close warehouse with Circle button on PS5 DualSense / DualShock 4 controllers (HID Raw Input)
- New: Registers for WM_INPUT HID GamePad + Joystick to receive controller data independently of game's input system
- New: Supports DualSense (USB/BT), DualSense Edge, DualShock 4 v1/v2 (USB/BT) via Sony VID 0x054C detection
- New: Deferred close — warehouse closes on Circle release (not press) to prevent dodge roll in gameplay
- New: Configurable PSButton for PS5/PS4 controllers (Share, Options, Circle, Triangle, Square, Cross, L1, R1, L3, R3, Touchpad, PS, Mute, none)
- New: Game-initiated close detection via +0x118 flag transition (1→0) — properly restores mode bytes and cursor
- Includes all v1.1.2 improvements: vtable auto-capture, dynamic panelId, INT3 padding, RIP-relative detection, spinlock, pre-activation

v1.1.2 (2026-03-31)
- Fixed: Auto-capture now identifies warehouse controller by vtable instead of panelId (compatible with UI-mods like "No Letterbox" that change panel registration order)
- Fixed: PanelId resolved dynamically from the warehouse handler object (no longer hardcoded 0x59)
- Improved: FindFunctionStart now recognizes INT3 padding (0xCC) as function boundary (MSVC standard)
- Improved: FindFunctionStart supports 3 additional prolog patterns (mov [rsp+8],rbx / push rbp;mov rbp,rsp / push rbp;sub rsp)
- Improved: Hook installation aborts safely if RIP-relative instructions detected in first 14-15 bytes (prevents silent corruption on game updates)
- Improved: Mode byte read/write protected by spinlock to prevent race condition between mod and game thread
- Changed: Removed ControllerEnabled toggle — controller works automatically when a ControllerButton is configured

v1.1.1 (2026-03-30)
- New: Mouse cursor now appears automatically when opening warehouse with keyboard (vanilla hides it)
- New: Cursor is hidden again when closing warehouse
- Changed: ESC close now uses the same PostMessage path as all other triggers (consistent behavior)

v1.1 (2026-03-30)
- Fixed: CanShow hook now correctly suppresses only competing store panels (IndulgenceView/BountyShop) while letting non-store UI work normally
- Fixed: Removed unsafe brute-force SetTitle scan that could cause silent memory corruption
- Fixed: SetTitle pattern now matches exact function start (off-by-one corrected)
- Fixed: DLL unload now properly restores all game hooks (prevents use-after-free crashes)
- Fixed: WndProc hook no longer falsely reports failure when previous WndProc was class-level
- Fixed: B button on controller now always closes warehouse (like ESC on keyboard), no ControllerButton config needed
- Improved: Function resolution now uses string cross-references instead of fragile byte patterns (survives game updates)
- Improved: Pattern scans kept as fallback if string-xref fails
- Improved: ModeSwitcher pattern scan now validates matches (was 9 matches, only 1 correct)
- Changed: Bottom inventory label correctly set to "Private Storage"
- Known issue: Top header may still show previous NPC name (e.g. "Camp Provisions") — cosmetic only, items are correct

v1.0.0 (2026-03-29)
- Initial release
- Open Private Storage from anywhere with F6
- ESC or F6 to close
- Auto-capture via panel ID — no chest visit required
- Pattern-scan based function detection (update-proof)
- Safety system: blocked during cutscenes, minigames, and interactions
- Configurable hotkey via INI file
